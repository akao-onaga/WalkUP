# Walk UP! ブラウザ版 — 画面デザインの見本

SwiftUI で画面を書くときに**先に見る物**。遊べる状態で置いてあるので、
「この画面はどう見えるべきか」を言葉ではなく動く物で確かめられる。

```bash
open web/index.html
```

素材（立ち絵・背景）は `WalkUP/Assets.xcassets/` を直接参照している。複製していないので、
アートを差し替えればこちらにも反映される。歩数だけはブラウザに存在しないため、
画面下の**開発用トレイ**から手で入れる（アプリには無い画面）。

進行は `localStorage` に入る。作り直したいときはトレイの「最初から」。

---

## 1. なぜ AI に書かせると健康アプリになるのか

**色や書体の問題ではない。構造の問題。**

角丸のカードを縦に等間隔で積み、カード1枚につき「小さな見出し＋大きな数値」を置く。
一覧は行で組み、右端に `>` を出す。見出しは `.navigationTitle`、記号は SF Symbols。
これは iOS の標準部品が最短距離で作れる形であり、**健康アプリ・習慣化アプリそのもの**でもある。

一度これを線と影だけ作り替えて失敗した。枠を凝っても、縦積みのカードは縦積みのカードだった。

## 2. 効いた一手：画面を2種類に分ける

**世界（ホーム・討伐・戦闘）** … アートが**地**。画面いっぱいに敷き、UI は暗い札として上に浮く。
**帳面（装備・図鑑・地域・道標・パス）** … 紙が**地**。下から上げて、開いて読む場面にする。

紙の上に絵を貼るのではなく、**絵の上に UI を浮かせる**。順序を逆にしただけで顔が変わる。
そして対比があるから、ホームが「外にいる」に、シートが「本を開いた」に見える。

戦闘だけが最初からゲームに見えていたのは、この構造になっていたのが戦闘だけだったから。

**混ぜないこと。** 世界の画面に紙色のカードを1枚置くと、暗い絵の上に書類が貼られたように浮く。
帳面に暗い札を混ぜても同じ。判定は「地は絵か紙か」だけ。

## 3. 守る規則（これを外すと元に戻る）

| # | 規則 | 破った時に起きること |
|---|---|---|
| 1 | 世界の画面はアートを全面に敷く。額に入れて縮めない | 「絵の入った書類」になる |
| 2 | 一覧を行で組まない。地図・格子・盤面にする | 行＋`>` は設定画面 |
| 3 | 同じ幅のボタンを縦に積まない。主となる一手を大きく、残りは丸い衛星 | フォームの送信ボタン列になる |
| 4 | 数値を四角い札に入れない。位は丸い紋章、資源は丸めた札 | 帳票になる |
| 5 | 面には必ず 2px の線（紙なら `#2E2A38`、世界なら紙色の 82%） | 線の無い面が1枚混じるとそこだけ標準アプリの顔 |
| 6 | 影はぼかさない。真下に 3px ずらした硬い影だけ | ぼかした影＝マテリアル＝アプリの顔 |
| 7 | 角丸は四隅で半径を変える | 四隅が同じだと定規で引いた図形＝UI 部品 |
| 8 | 見出しは**墨の帯**で打つ（帳面）／**地名**を出す（世界） | 細字＋下線はフォームの節見出し。アプリ名は看板であって画面ではない |
| 9 | 記号は自前で持つ。SF Symbols を使わない | 線の太さも造形もアートと揃わず、OS の顔が出る |
| 9b | **概念は記号（SVG）、世界に在る物は絵（生成）** | 物を記号にすると世界の手触りが消える。記号で足りる所を絵にすると重くなるだけ |
| 10 | 数値は等幅・極太。0 から回して止める | 完成値を置くだけでは「今日も無駄じゃなかった」が伝わらない |
| 11 | ゲージには輪郭線と目盛りを入れる | 線の無い細いバーは標準部品にしか見えない |
| 11b | **目盛りは飾りではなく単位にする**（細い刻み＝1,000歩＝活力1、太い刻み＝5,000歩） | 等分しただけの目盛りは模様で、読んでも何も分からない |
| 11c | **単位は数値より小さく落とす**（`歩` は 0.78em） | 同じ大きさで並べると、どちらが主かが決まらない |
| 11d | **押せない時は理由を書く**（「あと 8」「ノード1を討伐すると道が開く」） | 薄くして黙らせると、壊れているのか条件不足なのかが分からない |
| 11e | **当たり判定は 44px を最低線**にする（見た目は変えず透明な判定を重ねる） | 小さな札は 33px しかなく、指では外す |
| 12 | 標準のナビバー・Form・List を出さない | 開いた瞬間に設定画面になる |

## 5. 画面ごとの構図

### タイトル（`titleScreen`）— 世界
起動して最初に出る。ホームから題字を外した代わりに、**アプリの顔はここに置く。**

- 一枚絵は生成したもの（縦 9:16）。**文字は入っていない** — 生成に文字を描かせると綴りも字形も崩れる
- 題字は組版で載せる。白抜き＋太いインクの縁取り＋硬い落ち影。`Walk` は生成り、`UP!` は琥珀
- 触れば即座に抜ける。毎回見せる画面なので足止めにしない

### プロローグ（`PROLOGUE`）— 世界
タイトルを触った直後、歩数の許可を聞く前に一度だけ。2場面。

ダルモンが現れて世界が歩くのをやめ、**ただ一人だけ侵されなかった**——という筋。

- **講義にしない。** 「ダルモンとは人から気力を抜く存在であり」と定義から入ると、
  最初の30秒で取扱説明書の顔になる。見えている物と、起きたことだけを書く
- **前半は主人公を出さない**（`hero: false`）。まだ誰も歩いていない世界なので、
  そこに立っていると筋が合わない。「ただ一人を除いて」で初めて立たせる
- ここで世界を語るので、導入画面は**権限の話だけ**に戻せる

### 初回の導入（`introScreen`）— 世界
歩数を読ませてもらう前に、なぜ要るのかを言う。

**「アクセスを許可してください」だけでは通らない。** 審査（§11）でも要求されるが、
それ以前に、開いた直後の人にとってこれは見知らぬアプリからの要求でしかない。
何のために読むのか、読んだ数がどこへ行くのかを、世界の言葉で先に言う。

- 箇条に**点を打たない**。印を打つと約款に見える
- 「いまはデモで遊ぶ」を必ず置く。断った人が行き止まりに入らないようにする
- §15-4 の「通知は第1章クリア後」とは分けて考える。歩数は無いと何も始まらないので最初に聞く

### 完結（`endingScreen`）— 世界
第3章のボスを倒した後に一度だけ。

**「クリアしました」で終わらせない。** §5.3 のとおりダルモン本体を倒しても
世界の完全復興は達成されていない。ここで終わりだと告げると、続ける理由がその場で消える。
**まだ戻っていない地域を活気ゲージ付きで並べ、復興へ渡す。**

### 設定（`settingsScreen`）— 帳面
**標準の `Form` を使わない（2026-07-27 決定）。**

当初は「設定だけは OS の作法に従う方が迷わない」としていたが、その判断は取り消した。
**開いた瞬間に iOS の灰色のリストが出れば、それまで作った世界は一枚で消える。**
迷わせない責任は部品の出自ではなく**行の構造と言葉**が負う。
切替は同じ挙動を持つ自前の部品（`.segment` / `.switch`）で作り、並びと余白を標準に合わせる。

Swift 側の `SettingsView` はまだ `Form` のまま。**移植の対象として残っている。**

- 直近7日は**数だけの一覧にしない**。棒を添えると、歩いた日と歩かなかった日が形で分かる
- 1日の上限のような「変えられないが知りたいこと」も行として置く

### 場面（`sceneScreen`）— 世界
物語を出す共用の部品。チュートリアル（§11.1）・章の扉・ボスの前後・活気の節目で共用する。

#### 3種を書き分ける（`N` / `S` / `SYS`）

**全部を地の文で書くと、説明が説明のまま出てくる。**
「澱は靴に染み込ませられる」は仕様の説明であって、世界で誰も言っていない文になる。

| 種類 | 何を書くか | 見た目 |
|---|---|---|
| `N(text)` | 地の文。**見えている物と、起きたことだけ** | 白文字 |
| | ↑ **視点はウォークの目に固定し、主語を置かない。時制は過去を基調。** | |
| `S(who, text)` | セリフ。話者を必ず持つ | 話者の墨札＋鉤括弧。**本人だけ札が暖色** |
| `SYS(text)` | **世界の言葉にできない事実**（獲得・解放・数値） | 琥珀の細い帯 |

- **説明はできるだけ人に言わせる。** 強化の仕組みは工房の主が喋る。
  地の文で書くと、そのまま取扱説明書になる
- **システムは送らない**（文字送りしない）。読み上げる言葉ではないので、
  1文字ずつ出すと機械の報告に芝居をさせているように見える
- 鉤括弧は**組版側で付ける**。データに書かせない

#### 1行ずつ踏む（`linePlayer`）

**積み上げない。** 1つの札に足していくと、読み終わる頃には6行の塊になり、
場面ではなく**記録**に見える。1行ずつ置き換えて、触るたびに次が来る形にする。

触った時の挙動は2段。**送っている途中ならその行を最後まで出す、出し終わっていれば次の行へ。**
読み終える前に飛ばされない。最後の行まで来たら、画面を触っても進む手と同じ扱いにする。

- **札の高さを固定する**（2行ぶん）。行の長さで伸び縮みすると、踏むたびに画面が跳ねる
- **間は行として書く**（`HOLD(ms)`）。文字を出さずにその長さだけ待ち、待ち終われば
  自分で次の行へ進む——**踏ませない**（タップを1回余分に要求すると、間ではなく手数になる）。
  待っている最中に触れば飛ばせる。前の行は消さずに残し、▼ も出さない
  （待っているのはこちらであって、相手ではない）。
  **数を絞ること。** いまは5か所だけ——返事が無いこと・名を呼ばれること・
  一度も喋らなかったものが口を開くこと。**沈黙そのものが本文になる所にしか置かない**
- 次を促す `▼` は**待っている間だけ**出す。出しっぱなしだと、送っている最中にも押せると読める
- 章の扉も同じ部品を使う。3行を一度に置くと、読むか読まないかを選ばれる

主人公の声：**熱血。** 一人称は「俺」。前を向いていて、諦めない。
世界が静かで冷えているぶん、**一人だけ熱いという対比**で立たせる。
「ウォーク力」（DESIGN.md §1.1 のコピー語）を本人に言わせてよい唯一の場所がセリフ。

**ただしナレーションは熱くしない。** 地の文まで勢いを付けると、
世界そのものが元気な話になり、「止まった世界」という前提が消える。熱を持っているのはウォークだけ。

**帳面にしない。** 紙面で読ませると読み物になる。物語は「その場所で起きていること」なので、
地はその街のアートのままにして、文字だけを暗い札に載せる。章の扉と同じ作りを、
複数行と後始末（歩数の付与・装備画面への受け渡し）が要る場面向けに広げたもの。

- 立ち絵は**上にだけ余白を置く**。上下で挟むと画面の真ん中に浮き、
  背景に描かれた道より高い位置に立つので宙に浮いて見える
- 送り終わるまで進むボタンは `visibility: hidden` で**場所だけ空けておく**。
  出た瞬間に他が動くと、読んでいる行がずれる
- 触れば最後まで飛ぶ（章の扉・道標と同じ作法）

#### 街の人が出入りする（`PEOPLE` / `personArt`）

**セリフだけで姿が無いと、街の人は起きていないのと同じ。**
この作品の背骨は「人々を起こしていく」なので、起きた人は画面に立たせる。

配役は場面データに書かない。`S(who, …)` の who をそのまま鍵にして、
**その人が初めて喋る行で入ってくる**（`data.js` の `PEOPLE`）。
書き足した場面が黙って追従するので、場面と配役の二重管理にならない。

- **入り方を2通り持つ**（`enter`）。歩いて来る人（`walk`）と、戸や窓の内側にいる人（`fade`）。
  老女は二階の窓から、工房の主はシャッターの隙間から声をかける。
  **その人たちが右手から歩いて来ると、書いてある場所と絵が食い違う**
- 立ち絵は**同時に1人まで**。別の人が喋り出したら、先にいた人は去る。
  入れ替わりを黙って差し替えない
- 入り終わったら待機の揺れ（`bob`）へ引き渡す（ホームの主人公と同じ受け渡し方）
- **喋っている者だけを明るくし、他を落とす**（`speaking` / `hushed`）。
  立ち絵が並ぶと、札の名前を読むまで誰の声か分からない。
  地の文とシステムでは誰も強調しない——語り手は画面の中にいない
- 明暗は `filter` で作る。**`transform` は使わない**。待機の揺れが transform を握っているので、
  ここで動かすと揺れが止まる
- ダルモンは `PEOPLE` に入れない。第3章の対峙で喋るが、既に `foe` として立っている
- **表情差分は持たない**（2026-07-28 の方針）。1人1枚のまま、入り方・揺れ・明るさで感情を出す。
  生成回数がそのまま費用になるため（DESIGN.md §10.1.1）
- 喋る一拍は `voiceOf`（次項）。**去らせる時は say-* も外すこと。**
  CSS で `npc-fade-out` より後に書いてあるので、残すと**去る動きの方が負けて、
  その場で消えたように見える**
- 場面を出る時は、**人が去る一拍を挟んでから**次へ渡す（260ms）。
  人を残して画面だけ切り替えると、転換に間が無い
- 立ち絵が無い人は**影絵に落ちる**（`onerror`）。絵は後から足せるが、
  壊れた印は画面をそのまま壊す。影絵に顔は描かない——描くと本物の立ち絵と別人に見えるうえ、
  影絵のままでも成立してしまって生成が後回しになる

#### セリフに表情を付ける（`voiceOf`）

話者の札が変わるだけでは、驚きも焦りも同じ見え方になる。
かといって行ごとに感情を書かせると、35本に付ける手間がかかるうえ、
**書き足すたびに指定を忘れて無表情に戻る。**

**感情はもう本文に書かれている。** 全35セリフを数えるとこうなっている：

| 話者 | 記号 | 本数 |
|---|---|---|
| ウォーク | 「！」を含む | **19 / 19** |
| 街の人 | 「！」を一度も使わない | **16 / 16** |

つまり話者名と記号を読めば足りる。立ち絵の配役を `who` から引いたのと同じ作法で、
**書き足した場面が黙って追従する。**

| 声色 | 条件 | 送り | 立ち絵 |
|---|---|---|---|
| 迫り | 話者がダルモン | 92ms（極端に遅い） | ゆっくり膨らんで戻る |
| 熱血 | 「！」を含む | 21ms | 下から突き上げ、跳ね返って収まる |
| 言い淀み | 「……」で始まる | 47ms | 浅く沈んで、ゆっくり戻る |
| 平 | それ以外 | 32ms | 動かさない |

- **分け方は3つで止める。** 記号と感情は1対1ではないので、増やすほど
  外した時の見え方が説明できなくなる
- 「！」は**末尾ではなくどこかにあれば取る**。末尾だけ見ると
  「これ何に使えるんだ！？」が漏れる——勢いは「！」にあって、締めの「？」ではない
- 熱血を言い淀みより先に見る。「……なら、踏み越えていく！」は
  言い淀んで**から**踏み切る行なので、残るのは踏み切った側
- **傾けない。** 立ち絵はどれも正面に近い直立なので、回すと倒れかけて見える
  （ダルモンだけは元から形を持たないので膨らませてよい）
- **入ってくる行では一拍を出さない。** 登場そのものが既に動きで、重ねると入場が跳ねる
- `.scene-foe` は待機の揺れ用に `animation-delay: .7s` を持っている。
  **喋る一拍では 0 に戻すこと。** そのままだと喋ってから0.7秒後に動き出す

#### ボスが起き上がる（対峙 → 戦闘の橋・`revealBoss`）

直す前は、対峙の場面から暗転を挟んで戦闘画面へ飛び、**そこで初めて名前が出ていた。**
目の前にいたものが動き出す瞬間がどこにも無く、名乗りも場所違いだった。

**対峙の場では、ボスはまだ動いていない。** 文章がそう書いている——
第1章「畳まれて置かれていた」、第3章「動かずにいた。追ってはこない」。
だから**潰れた姿のまま立たせておいて、読み終えてから起き上がらせる。**

読み終えた後の順番：**街の人が下がる → 起き上がる → 名乗る → 戦う。**

| 章 | ボス | 潰れ方 → 起き上がり方 |
|---|---|---|
| 1 | マドロミ | 低く横に広い → **先に横へ張ってから縦へ伸びる**（いきなり縦だと布団でなく棒が生える） |
| 2 | ムキリョク | 縦に沈む → 頭が上がる。**重さを残す** |
| 3 | ダルモン | 縮こまる → 膨らんで迫る。**跳ねない**（「ただ、待っている」ものに勢いを付けると別の生き物になる） |

- **潰れているあいだは待機の揺れを与えない。** 揺れていたら、もう動いている
- **潰れているボスには喋る一拍も与えない**（`playMotion` で弾く）。
  第3章のダルモンは対峙の場で喋るが、動くのは起き上がる時まで取っておく
- 原点は必ず足元（`50% 100%`）。中心にすると潰れた時に地面へめり込み、起き上がる時に浮く
- 起き上がりの最中に触られたら**進まずに先へ飛ばす**（`skipReveal`）。
  ここで場面を出てしまうと、橋そのものが見られない
- 名乗りは**起き上がってから。** 潰れたままの物に名前が付くと、
  名乗ったのが誰なのか画面の上で決まらない
- 名札は **`.world-inner` の外**に置く。あれは `z-index: 2` の重なり文脈を作るので、
  中に入れると紙目（`.screen::before` の 60）より上に出られず、**白のはずの字が灰色に沈む**
- 戦闘へは `break`（帯）で入る。**周回の討伐と同じ入り方をしない。**
  ここを通るのは章で一度きりなので、帯の長さは §2 の3分に響かない

**戦闘画面の黒幕は落とした。** 以前は毎回 1.75 秒かけて名前を掲げていたが、
名乗りは章で一度きりの物なので、**二度目から毎回掲げるのは紹介ではなく足止め**だった。
周回のボス戦はそのぶん早く始まる。圧だけは残す（低く落ちる音を、幕なしで鳴らす）。

### 施設（`facilityScreen`）— 地図の上に建ち、帳面で開く
活気の節目 45% で開く（§6.2）。地域ごとに中身が違う。

**標は地図の上に置く。** 街に在る物なので帳面に畳まない。ホームの衛星ボタンも増やさない
（既に5つあり、6つ目からは選ぶ場所ではなくなる）。**標の形はノードと変える**——
同じ丸だと「もう一つの敵」に見え、押す前に何かが分からない。

中は紙で開く。外（世界）から中（建物）へ入る対比が要る。地図の上に建てておいて
中も暗いままだと、押した手応えが返らない。

- **ウォークの軌跡** … 直近7日の歩き方を読んで靴に刻印を打つ。**届いていない条件も数値で出す**
  （何をすれば刻めるか分からないと、ここは「押せない画面」になる）
- **市** … 素材の交換。**同じ幅のボタンを縦に積まない**。装備の行と同じく札の右端に小さく置く
  （全幅のボタンを2つ重ねると、交換所ではなくフォームの送信欄になる）
- **掲示板** … 日替わりの残党。**依頼の一覧を作らない。** 画鋲で留めた紙が1枚あるだけにする。
  縦に積んだデイリークエストは習慣化アプリの語彙そのもので、§1 の失敗を仕組みの側から呼び戻す

### 通知の許可（`notifyAskScreen`）— 世界
**第1章クリア直後に一度だけ**（DESIGN.md §15-4）。初回起動では聞かない。

**催促の言葉を使わない。** 「毎日歩きましょう」「連続記録が途切れます」は
習慣化アプリの語彙そのもので、§1 の失敗を通知の側から呼び戻す。
知らせるのは**街に起きたこと**であって、こちらの行動への催促ではない。

### 章の扉（`chapterDoorScreen`）— 世界
新しい章に届いた時に**一度だけ**出す（`state.seenDoors` で記録）。

**章の解放を数字だけで伝えない。** 「第2章が解放されました」は進捗通知であって、
新しい土地に着いたことではない。その場所の絵と、世界の側の一行を置く。

- 地名は**木札**に載せる。夜色の札より、その世界に落ちている物の方が強い
- 絵は 16:9 で描いてあるので、縦画面では**額に入れた帯**として見せる。
  `cover` で埋めると 2.4 倍に拡大され、小さく立たせた主人公が巨大になって構図が壊れる
- 一行は文字送り。扉で足を止めるのは読ませたいからで、一度に出すと読まれない

### ホーム（`renderHome`）— 世界
アートを全面に敷き、その上に：

```
[位の紋 Lv]                    [⚡活力] [◈澱]
            第1章 ・ 2日目
           灯りの落ちた商店街                    (道標の標)
      ┌────────────────────────┐
      │   主人公が街に立っている   │   ← 画面で一番広い面積
      └────────────────────────┘
  ╱ 次の標的  ウズクマリ            ⚡1 ╲   ← 帯
  ┌ 今日 30,000 / 30,000 ▓▓▓▓ Lv UP ┐   ← 計器
  ╔════════ 討伐に出る ════════╗       ← 進む手（暖色）
   ○装備  ○図鑑  ○地域  ○パス           ← 衛星
```

アプリ名は出さない。**地名を出す。** 数値は開いた瞬間に 0 から回し、環とゲージも 0 から伸ばす。

### 討伐（`mapScreen`）— 世界
**1画面に1章の地図。** 8つのノードを縦に並べた一覧は、どう飾っても目次。

- 標は手で置いた不規則な座標（`PIN_SPOTS`）に配置し、下から上へ蛇行させる
- 道は通った区間が実線（暖色）、これから行く区間が点線。**線の種類だけで進行が読める**
- 次に挑む標だけ脈を打つ。討伐済みは判子、未開放は錠
- 標を選ぶ → 下端の帯に相手と数値が出る → 「挑む」。**押した瞬間に戦闘へ飛ばさない**
- 章は左右の矢で切り替える。タブや Picker を出さない
- 未開放の章は色を抜くだけ。暗くしすぎると何も見えず、行きたい気持ちが湧かない

非等比の `viewBox` で道を引くので `vector-effect="non-scaling-stroke"` が必須。
これが無いと線が縦に引き伸ばされて帯になる。

### 戦闘（`battleScreen` / `playBattle`）— 世界
勝敗は入る前に確定している（`Game.startBattle`）。ここはログの再生だけ。
1手の順序が手応えを作る。**動かす量ではなく、止める瞬間。**

```
踏み込み(0.35拍) → 命中で止める → HP減少・数値・土煙・画面揺れを同じ瞬間に集中
→ 戻す(0.3拍)
```

- 主人公は左、ダルモンは右（主人公は右へ歩く絵なので、踏み込みの向きと噛み合う）
- 命中の跡は**土煙と靴底**。斬撃にしない（武器は靴）
- 撃破は**溶け落ちる**（縦に潰して横に広げる）。跡に澱の溜まりを残す
- 被弾時、主人公は明度を上げない（髪の輪郭が白飛びして頭が欠けて見える）
- ダメージ数値は立ち絵の**上端**に、太いインクの縁取りで出す（顔に重ねない）
- 立ち絵は透過で影を持たないので、接地の影は UI 側で足す

### 結果（`resultScreen`）— 世界
**紙に戻さない。** 戦った場所の上で締める。紙面に切り替えると熱が切れて領収書になる。
判子は傾いた状態から一気に縮み、少し傾いたまま止まる。獲得物は絵札を1枚ずつ。
敗北時は必ず「装備を強化する」への導線を置く（DESIGN.md §4.3）。

### 図鑑・地域・道標・装備 — 帳面
下から上げる紙のシート。上端に世界が覗くので「外で本を開いた」に見える。

- 図鑑は**格子**。縦一列の行にすると連絡先アプリになる。未発見は「？」、目撃のみは影
- 「世界の記述」は**読み物**。1件1カードにすると通知の一覧になる。紙面に直接組み `◆` で区切る
- 未読の記述は「まだ読めない」と書かず、**文字を伏せた紙面**（灰の破線）を見せる
- 道標の開封結果は、拾った物（絵札）と読み物（本文）を分ける
- 強化段階は数字ではなく目盛り（`.pips`）

## 6. 演出と動き

### 6.1 世界が動き出す（`worldLayers`）

**この作品の主題は「止まった世界が、歩いた分だけ動き出す」。**
それをシートの中の数値とバーで済ませていては、活気という仕組みは無いのと同じ。
活気（§17.9）を `life = 活気 / 100` の一つの値にして、風景の状態そのものにする。

| 層 | life が上がると |
|---|---|
| `.world-alive` | 復興後の背景が `opacity: life` で重なる（`bg{n}_alive`。同構図でなければ意味がない → ART_PROMPTS §3.7.1） |
| `.lamp` | 灯りが 12% / 45% / 75% の段階で1つずつ点く。**同時に点けると照明のスイッチに見える**。絵に灯りが描かれている今は光源ではなく「にじみ」なので濃さを 45% に落としてある |
| `.mote` | 空気中の粒が増え、灰から暖色へ変わり、速く漂う |
| `.distant` | 未討伐のダルモンが遠景にうずくまっている。討伐すると溶けて消える |
| `.life-mark` | 地名の下の短い目盛り。**数値は書かない** |

**前に見せた状態から動かす**（`shownLife` → `settleLife`）。討伐から戻ったとき、
いきなり明るい街が出ても「増えた」ことは伝わらない。前回の生気で描いてから遷移させると、
灯りが1つ増える瞬間が見える。

背景は 24 秒周期で 3.5% だけ膨らませ続ける（`breathe`）。**気づかれない大きさに留める。**
完全な静止画は「止まった世界」ではなく「ただの画像」に見える。

### 6.2 場面転換

| 場面 | 演出 |
|---|---|
| 討伐へ出る | **主人公が歩き去ってから**地図が開く（`walk-out` → `wipeTo`）。その場で差し替わると「画面遷移」だが、歩いて出て行くと「移動」になる |
| 戦闘へ入る | 上下の帯が逆方向から閉じ、逆へ抜ける（`#wipe`）。斜めに傾けるのは、水平の帯だと画面分割の UI に見えるため |
| 帳面を開く | 下から上げる。上端に世界が覗く。**下へ払えば閉じる**（`makeSwipeToClose`）。指に付いてきて、100px 引いたら閉じ、浅ければ戻る |
| 章を送る | 地図は**左右に払っても**送れる（`makeSwipeHorizontal`）。矢だけにすると、地図なのに歩けない |
| 標を選ぶ | 跳ねてから収まる。枠の色が変わるだけでは選んだ手応えが返らない |
| ホームを開く | 主人公が左から歩いて入り、待機の揺れへ引き渡す（`walk-in` → `bob`） |

#### 転換には「格」がある（`Nav.beat`）

直す前は、**28場面すべてが同じ 0.22 秒のクロスフェード**で並んでいた。
「すぐ次」も「場所が変わった」も「章が終わった」も同じ見え方をするので、
**転換そのものが何も言っていない**状態だった。間が無いのではなく、階調が無かった。

| 格 | いつ | 見え方 | 使う所 |
|---|---|---|---|
| `cut` | 同じ場所で、直後に続く | いまのまま速い | 場面 → ホーム |
| `move` | 時か場所が変わる | 黒へ落とし、**黒のまま置いてから**出す | プロローグ・導入・チュートリアル・山場・活気の節目・通知 |
| `break` | 章の境目 | 斜めの帯。溜めが一番長い | 章の扉・完結 |

**道具は増やしていない。** 戦闘で使っていた暗転と、討伐で使っていた帯を、
場面の連結にも回しただけ。新しい見え方を足すと、既に覚えた合図と競合する。

- **戦闘への入りは `beat` に載せていない**（`curtainTo` のまま）。周回で毎日通る道なので、
  物語と同じ長さの溜めを毎回挟むと §2 の「1セッション3分」を討伐の側から食い潰す。
  **同じ暗転でも、初めて見る場面と毎日見る画面では要る長さが違う**
- 幕の裏で積んだ画面には `.static` を付けて、**現れる動きを止める。**
  幕が上がる 0.22 秒と `.cover` の 0.22 秒が重なると、**両方が半透明になって
  前の画面が透ける**（ホームの上にプロローグが乗って、両方が同時に見えた）
- `.screen.static` は **`.screen.cover` より後に書くこと。** 詳細度が同じなので、
  前に置くと打ち消せない（長いあいだ効いていなかった）

#### カメラ（`shot-close` / `shot-wide`）

背景は完全な静止画だった（`breathe` の 24 秒周期 3.5% だけ）。
**寄るか引くかは、その場面が誰の話かで決まる。**

- **寄る** … 一人に絞る場面。対峙、誰かが目を覚ます瞬間
- **引く** … 街ぐるみ・世界の話。灯りが並ぶ、道ができる
- **指定しない** … 淡々と進む場面。**全場面を動かすと、どの場面も同じ「動く絵」になる**

指定は `data.js` の `SHOTS` に**一覧で持つ**（場面データに散らすと、
28場面ぶんの寄り引きの並びが読めなくなる）。チュートリアルとプロローグだけは
場面オブジェクトを自前で持っているので、そちらに直接書く。

- **呼吸を置き換える**（重ねない）。同じ要素の transform を取り合って震える
- **一度動いて止まる。** ずっと寄り続けると、読んでいるあいだ絵が落ち着かない
- 寄る時の原点は足元側（`50% 66%`）。中心にすると、人物ではなく空へ寄っていく

### 6.3 文字送り（`typeInto`）

「世界の記述」は**置くのではなく送る**。完成した文章を一度に出すと、目に入った瞬間に
「読むか読まないか」を選ばれてしまう。1文字ずつ出れば、もう読み始めている。

- 句読点の後だけ長く置く（読点 6倍・句点 10倍）。均等に送ると機械の出力に見える
- **触れば最後まで飛ぶ。** 待たされる読み物は二度と開かれない
- 送るのは道標で新しく引いた時だけ。地域画面の読み返しは即座に出す

### 6.4 戦闘

- **とどめだけ、振りかぶってから止める時間を倍にする。** 速さが一定だと決着が他の手と同じ重さになる
- ボスは名乗ってから始める（`boss-intro`）。雑魚と同じ入り方だと、ただの強い個体になる
- 残り 30% を切った計器は脈を打つ（`.critical`）。**数字を読ませずに危うさを伝える**
- 手数は帯に出す（「第1章 ・ ノード8 ・ 11手目」）

### 6.5 音（`sound.js`・試作）

**音源ファイルを持たない。** すべて WebAudio の合成。素材の購入も権利処理も要らず、
鳴らして要否を判断できる。本編で採用するなら、ここで決まった「長さ・高さ・減衰」を
仕様として渡す。開発用トレイの「音: ON/OFF」で切れる。

設計は触覚と同じ。**強い音を1か所に集中させる。** すべてを鳴らすとどれも意味を失う。

| 合図 | 音 | 方針 |
|---|---|---|
| `tap` | 620Hz 50ms | 押すたび鳴るので限界まで小さく |
| `step` / `hit` | 低域の雑音＋鈍い正弦 | 土と砂利。金属音・電子音にしない |
| `hurt` | 更に低く長い | 自分が受けた時だけ重くする |
| `melt` | 320→70Hz 0.75秒 | 倒したのではなく溶けたので余韻を残す |
| `gain` | 784Hz＋倍音 | **ここだけ倍音を持たせる。手応えの本体** |
| `levelup` | 4音の分散和音 | レベルが上がった日だけ |
| `type` | 20ms の微小な雑音 | 聞こえるか聞こえないかでいい |

### 記号か絵か

| 対象 | 扱い | 理由 |
|---|---|---|
| 活力・戻る・閉じる・鍵・目・活気 | SVG の記号（`icon()`） | 概念。色を継承させたいし、物として存在しない |
| 靴・外套・護符（9点） | 生成した絵（`itemOf()`） | 拾って持ち歩く物。段位の差も絵で出る |
| 澱・核・かけら | 生成した絵 | 同じ。こちらは堕落した側なので灰紫 |
| 主人公 | 走り姿と**立ち姿**の2枚 | ホームは歩いて来て立つ、装備は立ち姿、戦闘は走り姿 |
| 道標・溶けた跡・靴底の跡・木札 | 生成した絵 | 世界に在る物。CSS の楕円や角丸矩形では厚みも溝も出ない |
| 章の扉絵3枚・タイトルの一枚絵 | 生成した絵 | 場所そのもの。題字だけは組版（生成に文字を描かせない） |

作り方と失敗（透過をアルファで頼むと市松模様が焼き込まれる）は
`ART_PROMPTS.md §3.7.2` に手順ごと書いてある。
| `ui.js` | 画面と演出 | `WalkUP/UI/*.swift` |
| `style.css` | **意匠（本体）** | `Theme.swift` |

数値は `data.js` にしか書かない。ブラウザ版と本編で数字がずれると、
「この見た目でこの手応え」という判断そのものが当てにならなくなる。
