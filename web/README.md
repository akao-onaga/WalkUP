# Walk UP! ブラウザ版 — 画面デザインの見本

SwiftUI で画面を書くときに**先に見る物**。遊べる状態で置いてあるので、
「この画面はどう見えるべきか」を言葉ではなく動く物で確かめられる。

```bash
open web/index.html
```

素材（立ち絵・背景）は `WalkUP/Assets.xcassets/` を直接参照している。複製していないので、
アートを差し替えればこちらにも反映される。歩数だけはブラウザに存在しないため、
画面下の**開発用トレイ**から手で入れる（アプリには無い画面）。

進行は `localStorage` に入る。作り直したいときはトレイの「最初から」。

---

## 1. なぜ AI に書かせると健康アプリになるのか

**色や書体の問題ではない。構造の問題。**

角丸のカードを縦に等間隔で積み、カード1枚につき「小さな見出し＋大きな数値」を置く。
一覧は行で組み、右端に `>` を出す。見出しは `.navigationTitle`、記号は SF Symbols。
これは iOS の標準部品が最短距離で作れる形であり、**健康アプリ・習慣化アプリそのもの**でもある。

一度これを線と影だけ作り替えて失敗した。枠を凝っても、縦積みのカードは縦積みのカードだった。

## 2. 効いた一手：画面を2種類に分ける

**世界（ホーム・討伐・戦闘）** … アートが**地**。画面いっぱいに敷き、UI は暗い札として上に浮く。
**帳面（装備・図鑑・地域・道標・パス）** … 紙が**地**。下から上げて、開いて読む場面にする。

紙の上に絵を貼るのではなく、**絵の上に UI を浮かせる**。順序を逆にしただけで顔が変わる。
そして対比があるから、ホームが「外にいる」に、シートが「本を開いた」に見える。

戦闘だけが最初からゲームに見えていたのは、この構造になっていたのが戦闘だけだったから。

**混ぜないこと。** 世界の画面に紙色のカードを1枚置くと、暗い絵の上に書類が貼られたように浮く。
帳面に暗い札を混ぜても同じ。判定は「地は絵か紙か」だけ。

## 3. 守る規則（これを外すと元に戻る）

| # | 規則 | 破った時に起きること |
|---|---|---|
| 1 | 世界の画面はアートを全面に敷く。額に入れて縮めない | 「絵の入った書類」になる |
| 2 | 一覧を行で組まない。地図・格子・盤面にする | 行＋`>` は設定画面 |
| 3 | 同じ幅のボタンを縦に積まない。主となる一手を大きく、残りは丸い衛星 | フォームの送信ボタン列になる |
| 4 | 数値を四角い札に入れない。位は丸い紋章、資源は丸めた札 | 帳票になる |
| 5 | 面には必ず 2px の線（紙なら `#2E2A38`、世界なら紙色の 82%） | 線の無い面が1枚混じるとそこだけ標準アプリの顔 |
| 6 | 影はぼかさない。真下に 3px ずらした硬い影だけ | ぼかした影＝マテリアル＝アプリの顔 |
| 7 | 角丸は四隅で半径を変える | 四隅が同じだと定規で引いた図形＝UI 部品 |
| 8 | 見出しは**墨の帯**で打つ（帳面）／**地名**を出す（世界） | 細字＋下線はフォームの節見出し。アプリ名は看板であって画面ではない |
| 9 | 記号は自前で持つ。SF Symbols を使わない | 線の太さも造形もアートと揃わず、OS の顔が出る |
| 10 | 数値は等幅・極太。0 から回して止める | 完成値を置くだけでは「今日も無駄じゃなかった」が伝わらない |
| 11 | ゲージには輪郭線と目盛りを入れる | 線の無い細いバーは標準部品にしか見えない |
| 12 | 標準のナビバー・Form・List を出さない | 開いた瞬間に設定画面になる |

## 5. 画面ごとの構図

### ホーム（`renderHome`）— 世界
アートを全面に敷き、その上に：

```
[位の紋 Lv]                    [⚡活力] [◈澱]
            第1章 ・ 2日目
           灯りの落ちた商店街                    (道標の標)
      ┌────────────────────────┐
      │   主人公が街に立っている   │   ← 画面で一番広い面積
      └────────────────────────┘
  ╱ 次の標的  ウズクマリ            ⚡1 ╲   ← 帯
  ┌ 今日 30,000 / 30,000 ▓▓▓▓ Lv UP ┐   ← 計器
  ╔════════ 討伐に出る ════════╗       ← 進む手（暖色）
   ○装備  ○図鑑  ○地域  ○パス           ← 衛星
```

アプリ名は出さない。**地名を出す。** 数値は開いた瞬間に 0 から回し、環とゲージも 0 から伸ばす。

### 討伐（`mapScreen`）— 世界
**1画面に1章の地図。** 8つのノードを縦に並べた一覧は、どう飾っても目次。

- 標は手で置いた不規則な座標（`PIN_SPOTS`）に配置し、下から上へ蛇行させる
- 道は通った区間が実線（暖色）、これから行く区間が点線。**線の種類だけで進行が読める**
- 次に挑む標だけ脈を打つ。討伐済みは判子、未開放は錠
- 標を選ぶ → 下端の帯に相手と数値が出る → 「挑む」。**押した瞬間に戦闘へ飛ばさない**
- 章は左右の矢で切り替える。タブや Picker を出さない
- 未開放の章は色を抜くだけ。暗くしすぎると何も見えず、行きたい気持ちが湧かない

非等比の `viewBox` で道を引くので `vector-effect="non-scaling-stroke"` が必須。
これが無いと線が縦に引き伸ばされて帯になる。

### 戦闘（`battleScreen` / `playBattle`）— 世界
勝敗は入る前に確定している（`Game.startBattle`）。ここはログの再生だけ。
1手の順序が手応えを作る。**動かす量ではなく、止める瞬間。**

```
踏み込み(0.35拍) → 命中で止める → HP減少・数値・土煙・画面揺れを同じ瞬間に集中
→ 戻す(0.3拍)
```

- 主人公は左、ダルモンは右（主人公は右へ歩く絵なので、踏み込みの向きと噛み合う）
- 命中の跡は**土煙と靴底**。斬撃にしない（武器は靴）
- 撃破は**溶け落ちる**（縦に潰して横に広げる）。跡に澱の溜まりを残す
- 被弾時、主人公は明度を上げない（髪の輪郭が白飛びして頭が欠けて見える）
- ダメージ数値は立ち絵の**上端**に、太いインクの縁取りで出す（顔に重ねない）
- 立ち絵は透過で影を持たないので、接地の影は UI 側で足す

### 結果（`resultScreen`）— 世界
**紙に戻さない。** 戦った場所の上で締める。紙面に切り替えると熱が切れて領収書になる。
判子は傾いた状態から一気に縮み、少し傾いたまま止まる。獲得物は絵札を1枚ずつ。
敗北時は必ず「装備を強化する」への導線を置く（DESIGN.md §4.3）。

### 図鑑・地域・道標・装備 — 帳面
下から上げる紙のシート。上端に世界が覗くので「外で本を開いた」に見える。

- 図鑑は**格子**。縦一列の行にすると連絡先アプリになる。未発見は「？」、目撃のみは影
- 「世界の記述」は**読み物**。1件1カードにすると通知の一覧になる。紙面に直接組み `◆` で区切る
- 未読の記述は「まだ読めない」と書かず、**文字を伏せた紙面**（灰の破線）を見せる
- 道標の開封結果は、拾った物（絵札）と読み物（本文）を分ける
- 強化段階は数字ではなく目盛り（`.pips`）

## 6. 演出と動き

### 6.1 世界が動き出す（`worldLayers`）

**この作品の主題は「止まった世界が、歩いた分だけ動き出す」。**
それをシートの中の数値とバーで済ませていては、活気という仕組みは無いのと同じ。
活気（§17.9）を `life = 活気 / 100` の一つの値にして、風景の状態そのものにする。

| 層 | life が上がると |
|---|---|
| `.world-alive` | 復興後の背景が `opacity: life` で重なる（同構図でなければ意味がない → ART_PROMPTS §3.7.1） |
| `.lamp` | 灯りが 12% / 45% / 75% の段階で1つずつ点く。**同時に点けると照明のスイッチに見える** |
| `.mote` | 空気中の粒が増え、灰から暖色へ変わり、速く漂う |
| `.distant` | 未討伐のダルモンが遠景にうずくまっている。討伐すると溶けて消える |
| `.life-mark` | 地名の下の短い目盛り。**数値は書かない** |

**前に見せた状態から動かす**（`shownLife` → `settleLife`）。討伐から戻ったとき、
いきなり明るい街が出ても「増えた」ことは伝わらない。前回の生気で描いてから遷移させると、
灯りが1つ増える瞬間が見える。

背景は 24 秒周期で 3.5% だけ膨らませ続ける（`breathe`）。**気づかれない大きさに留める。**
完全な静止画は「止まった世界」ではなく「ただの画像」に見える。

### 6.2 場面転換

| 場面 | 演出 |
|---|---|
| 討伐へ出る | **主人公が歩き去ってから**地図が開く（`walk-out` → `wipeTo`）。その場で差し替わると「画面遷移」だが、歩いて出て行くと「移動」になる |
| 戦闘へ入る | 上下の帯が逆方向から閉じ、逆へ抜ける（`#wipe`）。斜めに傾けるのは、水平の帯だと画面分割の UI に見えるため |
| 帳面を開く | 下から上げる。上端に世界が覗く |
| ホームを開く | 主人公が左から歩いて入り、待機の揺れへ引き渡す（`walk-in` → `bob`） |

### 6.3 文字送り（`typeInto`）

「世界の記述」は**置くのではなく送る**。完成した文章を一度に出すと、目に入った瞬間に
「読むか読まないか」を選ばれてしまう。1文字ずつ出れば、もう読み始めている。

- 句読点の後だけ長く置く（読点 6倍・句点 10倍）。均等に送ると機械の出力に見える
- **触れば最後まで飛ぶ。** 待たされる読み物は二度と開かれない
- 送るのは道標で新しく引いた時だけ。地域画面の読み返しは即座に出す

### 6.4 戦闘

- **とどめだけ、振りかぶってから止める時間を倍にする。** 速さが一定だと決着が他の手と同じ重さになる
- ボスは名乗ってから始める（`boss-intro`）。雑魚と同じ入り方だと、ただの強い個体になる
- 残り 30% を切った計器は脈を打つ（`.critical`）。**数字を読ませずに危うさを伝える**
- 手数は帯に出す（「第1章 ・ ノード8 ・ 11手目」）

### 6.5 音（`sound.js`・試作）

**音源ファイルを持たない。** すべて WebAudio の合成。素材の購入も権利処理も要らず、
鳴らして要否を判断できる。本編で採用するなら、ここで決まった「長さ・高さ・減衰」を
仕様として渡す。開発用トレイの「音: ON/OFF」で切れる。

設計は触覚と同じ。**強い音を1か所に集中させる。** すべてを鳴らすとどれも意味を失う。

| 合図 | 音 | 方針 |
|---|---|---|
| `tap` | 620Hz 50ms | 押すたび鳴るので限界まで小さく |
| `step` / `hit` | 低域の雑音＋鈍い正弦 | 土と砂利。金属音・電子音にしない |
| `hurt` | 更に低く長い | 自分が受けた時だけ重くする |
| `melt` | 320→70Hz 0.75秒 | 倒したのではなく溶けたので余韻を残す |
| `gain` | 784Hz＋倍音 | **ここだけ倍音を持たせる。手応えの本体** |
| `levelup` | 4音の分散和音 | レベルが上がった日だけ |
| `type` | 20ms の微小な雑音 | 聞こえるか聞こえないかでいい |

| `data.js` | マスターデータと定数 | `MasterData.swift` / `BalanceRules.swift` |

| `ui.js` | 画面と演出 | `WalkUP/UI/*.swift` |
| `style.css` | **意匠（本体）** | `Theme.swift` |

数値は `data.js` にしか書かない。ブラウザ版と本編で数字がずれると、
「この見た目でこの手応え」という判断そのものが当てにならなくなる。
