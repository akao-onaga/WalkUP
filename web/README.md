# Walk UP! ブラウザ版 — 画面デザインの見本

SwiftUI で画面を書くときに**先に見る物**。遊べる状態で置いてあるので、
「この画面はどう見えるべきか」を言葉ではなく動く物で確かめられる。

```bash
open web/index.html
```

素材（立ち絵・背景）は `WalkUP/Assets.xcassets/` を直接参照している。複製していないので、
アートを差し替えればこちらにも反映される。歩数だけはブラウザに存在しないため、
画面下の**開発用トレイ**から手で入れる（アプリには無い画面）。

進行は `localStorage` に入る。作り直したいときはトレイの「最初から」。

---

## 1. なぜ AI に書かせると健康アプリになるのか

**色や書体の問題ではない。構造の問題。**

角丸のカードを縦に等間隔で積み、カード1枚につき「小さな見出し＋大きな数値」を1つ置く。
リストは行で組み、行の右端に `>` を出す。見出しは `.navigationTitle`、
記号は SF Symbols、面には線を引かず薄い影だけ。

これは iOS の標準部品が最短距離で作れる形であり、**健康アプリ・習慣化アプリそのもの**でもある。
中の絵や言葉をどれだけ作り込んでも、構造が同じなら同じ顔になる。

このブラウザ版は、その構造を捨てて**画集の頁**として組み直したもの。
図版（絵）と紙面（文字）を分け、面には必ず線を引き、数値は札に載せる。

## 2. 守る規則（これを外すと元に戻る）

| # | 規則 | 破った時に起きること |
|---|---|---|
| 1 | 面には必ず 2px のインク線（`#2E2A38`）を引く | 線の無い面が1枚混じると、そこだけ標準アプリの顔になる |
| 2 | 影はぼかさない。真下に 3px ずらした硬い影だけ | ぼかした影＝マテリアルデザイン＝アプリの顔 |
| 3 | 角丸は四隅で半径を変える | 四隅が同じだと定規で引いた図形＝UI 部品に見える |
| 4 | 見出しは**墨の帯**（黒地に白抜き）で打つ | 細字＋下線はフォームの節見出し |
| 5 | 一覧を「行」で組まない。道・格子・盤面にする | 行＋`>` は設定画面 |
| 6 | 記号は自前で持つ。SF Symbols を使わない | 線の太さも造形もアートと揃わず、OS の顔が出る |
| 7 | 数値は等幅・極太。0 から回して止める | 完成値を置くだけだと「今日も無駄じゃなかった」が伝わらない |
| 8 | ゲージには輪郭線と目盛りを入れる | 線の無い細いバーは標準部品にしか見えない |
| 9 | 背景の絵を薄めない。額装して1枚の絵として見せる | 55% まで沈めた絵は「ぼやけた汚れ」で、世界がある感じは出ない |
| 10 | 標準のナビゲーションバー・Form・List を出さない | 開いた瞬間に設定画面になる |

## 4. 画面ごとの構図

### ホーム（`renderHome`）
上から **看板 → 図版 → 紙面**。

- **看板**: 黒地に白抜きでアプリ名。右端に日数。`.navigationTitle` は使わない
- **図版**: 高さ 206pt の額。今いる地域の背景絵を**そのままの濃さで**敷き、
  主人公を左に立たせる（`IdleBob` で待機、接地の影を UI 側で足す）。
  「今日も歩いた／その分だけ、世界が目を覚ます。」は**絵の中**に置く。紙面に降ろすと説明文になる
- **紙面**: 級位の帯（Lv＋ゲージを横一列）→ 3枚の札（今日／活力／澱）→ 高札（次の目的地）→ 行動の札

数値は開いた瞬間に 0 から回す。ゲージも 0 から伸ばす。

### 討伐（`mapScreen`）
章は**扉**で開く。地域の絵を 72pt の帯で敷き、その下に**道**を1本引く。
ノードは道の上の**標**（円形メダル＋ダルモンの絵）。討伐済みは判子、未開放は錠前。
**行で組まない。**

### 戦闘（`battleScreen` / `playBattle`）
勝敗は入る前に確定している（`Game.startBattle`）。ここはログの再生だけ。

1手の順序が手応えを作る。**動かす量ではなく、止める瞬間。**

```
踏み込み(0.35拍) → 命中で止める → HP減少・数値・土煙・画面揺れを同じ瞬間に集中
→ 戻す(0.3拍)
```

- 主人公は左、ダルモンは右（主人公は右へ歩く絵なので、踏み込みの向きと噛み合う）
- 命中の跡は**土煙と靴底**。斬撃にしない（武器は靴）
- 撃破は**溶け落ちる**（縦に潰して横に広げる）。跡に澱の溜まりを残す
- 被弾時、主人公は明度を上げない（髪の輪郭が白飛びして頭が欠けて見える）
- ダメージ数値は立ち絵の**上端**に出す（顔に重ねない）。太いインクの縁取りを付ける

### 結果（`resultScreen`）
中身を上下中央に置く。判子が**傾いた状態から一気に縮んで、少し傾いたまま止まる**。
獲得物は**絵札を並べる**（行に「名前 …… ×3」と書くと納品書になる）。1枚ずつ順に出す。
敗北時は必ず「装備を強化する」への導線を置く（DESIGN.md §4.3）。

### 図鑑（`bestiaryScreen`）
**格子**。縦一列の行にすると連絡先アプリになる。
未発見は「？」、目撃のみは影（`brightness(0) opacity(.35)`）、討伐済みは絵と名前。

### 地域・道標（`regionScreen` / `milestoneScreen`）
「世界の記述」は**読み物**。1件1カードに入れると通知の一覧になる。
紙面に直接組み、`◆` で区切る。未読は文字を伏せた紙面（灰色の破線バー）として見せる。
道標の開封結果は、**拾った物（絵札）と読み物（本文）を分ける**。

## 5. ファイル

| ファイル | 中身 | Swift 側の対応 |
|---|---|---|
| `data.js` | マスターデータと定数 | `MasterData.swift` / `BalanceRules.swift` |
| `engine.js` | 戦闘・報酬・道標・状態 | `BattleEngine` / `RewardCalculator` / `MilestoneOpener` / `GameModel` |
| `ui.js` | 画面と演出 | `WalkUP/UI/*.swift` |
| `style.css` | **意匠（本体）** | `Theme.swift` |

数値は `data.js` にしか書かない。ブラウザ版と本編で数字がずれると、
「この見た目でこの手応え」という判断そのものが当てにならなくなる。
